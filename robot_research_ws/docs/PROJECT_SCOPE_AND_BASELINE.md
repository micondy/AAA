# 工程范围、基础功能与后续完善边界

更新日期：2026-09-13。

## 1. 工程总目标

本工程当前不是以一次性做成完整商品机器人为目标，而是先建立一个可靠、可重复、能够支撑
研究所论文实验的移动操作机器人平台。

基础工程需要形成以下闭环：

```text
地图可保存和重载
  -> 机器人可稳定定位
  -> Nav2 可把底盘送到任务区或观察位置
  -> RGB-D 感知输出目标位置及其不确定性
  -> MoveIt 可规划安全的机械臂动作
  -> 实验过程可记录、复现和比较
```

达到这个闭环后，应把主要精力转向主动感知研究，不继续无边界地扩展 SLAM、导航和硬件。

## 2. P02 是什么

`P02` 不是算法、ROS 节点或工程模块，只是导航测试文件中的第二个预设目标点，全名为
`P02_west_mid`。

目标点保存在：

```text
src/robot_research/navigation/mobile_navigation_bringup/
  config/isaac_indoor_top_rt_01_waypoints.yaml
```

当前坐标为：

```text
frame: map
x: -1.855 m
y:  3.339 m
yaw: 0.748 rad
```

之前使用纯 RGB-D 视觉里程计时，机器人完成第一个测试点 P01 后朝向一片低纹理区域，视觉
特征下降，随后执行 P02 时 `odom -> base_link` 中断约 20 秒。因此 P02 被保留为一个故障
复现点，用来检查切换到底盘连续里程计后，旧问题是否消失。2026-09-13 已完成严格的
P01→P02 连续回归：P01 和 P02 均成功，旧 TF 断层没有再次出现。

它本身没有特殊研究意义，也不是以后必须一直使用的点。验证完成后，可将 P01、P02 统一
称为“导航测试点 01/02”，也可以根据新地图重新生成测试点。

只执行 P02 的命令参数是：

```bash
ros2 run mobile_navigation_bringup navigation_waypoint_benchmark.py \
  --execute --start-index 2 --end-index 2
```

这只跑一个目标，不会执行全部 10 个目标。

## 3. 什么是导航基线

“导航基线”是供后续目标感知、主动视角和移动操作实验调用的最低可用导航系统。它不是最终
产品级导航，也不是论文的主要创新点。

当前导航基线包含：

```text
底盘里程计
  -> /swerve_controller/odom
  -> odom -> base_link

固定 D435i RGB-D + 底盘里程计
  -> RTAB-Map
  -> map -> odom
  -> 二维占据地图

Nav2
  -> 全局规划
  -> 前向低速路径跟踪
  -> 速度平滑
  -> 前向点云碰撞监控
  -> 底盘速度接口
```

导航基线达到以下程度即可冻结：

- 能建立地图、保存数据库并重新加载；
- `map -> odom -> base_link` 连续且没有重复 TF 发布者；
- 能完成 3～5 个具有代表性的短距离目标；
- 相机断流或障碍进入停止区时最终速度变为零；
- 能保存成功和失败实验的 rosbag、JSON 或 CSV；
- 仿真和实机尽量使用相同的上层话题与 launch；
- 失败时有清楚的错误记录，不要求任何环境下都能自主脱困。

当前已经完成外部底盘 odom、RTAB-Map 正式闭环建图、Nav2 四点验收和确定性障碍安全回归。
P01→P02 连续回归成功；到达低纹理朝向后底盘 odom 约 60 Hz，完整 TF 没有再次出现约
20 秒断层。2026-09-15 新地图四点导航 4/4 成功、0 次恢复，仿真导航基线至此冻结；实机
验收仍需等待电池、相机刚性安装和外参测量。

mask-depth 三维融合、多实例输出、跨帧基线 ID 和自动评测。基础感知当前状态为：

- [已完成] 从 RGB-D 中分割普通目标；
- [已完成] 输出目标三维位置、尺寸、坐标系和观测协方差；
- [已完成] 输出模型实例数、深度有效实例数、延迟和权重哈希；
- [已完成] 三维距离与类别门控的跨帧基线 ID；
- [已有单目标版本] 多帧 Target Belief、异常观测拒绝和短时可见性；
- [已完成] 从稳定 ID 中锁定一个关注目标并接入现有单目标 Belief；目标切换时自动重置；
- [已完成软件核心] 增加视锥、投影面积、入射角、深度遮挡率、预计观测协方差和信息增益；
- [联合仿真通过] 生成底盘观察候选，接入地图过滤和 Nav2 路径查询。多对象关联
  继续由感知层负责。

可以先用箱体、瓶子、工具或蘑菇做实验，但软件接口不应写死为蘑菇专用。

### 4.3 机械臂基础能力

- 统一 URDF 中保留官方 OpenArm 模型；
- MoveIt 能完成左右臂规划和执行；
- 自碰撞、底盘碰撞和任务场景碰撞有效；
- 能从上层接口调用一个安全观察姿态或操作姿态。

当前不需要立刻做底盘和双臂几十个自由度的联合优化。

### 4.4 实验基础设施

- 仿真和实机分别有清楚的一键启动入口；
- rosbag 记录相机、TF、odom、目标观测、belief、Nav2 状态和控制输出；
- 评测脚本输出 JSON/CSV；
- README 中保留可复制的启动、停止和单项回归命令；
- 每项结论都有数据文件，而不只依赖 RViz 截图。

## 5. 基础功能完成后的近期研究主线

固定顶部 D435i 暂时不移动机械臂相机，先实现底盘主动视角选择：

```text
当前 RGB-D 观测
  -> Target Belief
  -> 生成有限个底盘候选观察位姿
  -> 检查地图可达性、碰撞和目标可见性
  -> 预测不确定性下降
  -> 综合信息增益与运动代价评分
  -> Nav2 到达最佳候选
  -> 重新观测并验证 belief 是否改善
```

候选评分可包含：

```text
Score = 信息增益 + 可见性 - 导航代价 - 碰撞风险 - 定位风险
```

这部分才是近期最值得形成论文贡献的模块。导航在这里是执行载体，而不是研究终点。

## 6. 以后再完善的内容

### 6.1 实车导航与安全

- D435i 安装外参测量和标定；
- 轮速、转角与 D435i IMU 融合；
- 轮胎打滑、振动和里程计误差建模；
- 电池供电下的连续运行；
- CAN 断联看门狗、实体急停和真实停止距离；
- 实车地图重载和多次重复导航。

这些是实机实验必须完成的工作，但在底盘仍使用插座电源调试期间，不阻塞仿真主动感知。

### 6.2 另外两台 D435

等机械安装位置和用途确定后，再加入：

- 多相机时间同步和外参标定；
- 相机选择与观测质量比较；
- 点云去重或融合；
- 不同相机的噪声与协方差模型。

当前不直接拼接三台相机点云，也不创建不存在的腕部相机 TF。

### 6.3 三维与语义地图

二维占据地图足以支撑近期 Nav2 和底盘 NBV。只有研究问题明确需要时，再增加：

- OctoMap、TSDF 或 ESDF；
- 语义占据地图；
- 动态目标过滤；
- 目标级长期记忆；
- 可见性和遮挡地图。

### 6.4 全身主动感知

建议按以下顺序扩展：

1. 底盘把机器人送到任务区域；
2. 固定相机底盘 NBV；
3. 安装位置明确后增加机械臂或腕部相机候选；
4. 最后才联合选择底盘和机械臂动作。

### 6.5 更远期功能

- 开放词汇检测和语义导航；
- 视觉语言模型；
- 强化学习或端到端控制；
- 三相机大规模融合；
- 温室蘑菇专用任务规划；
- 多机器人协作。

这些都不属于当前基础功能，不应阻塞第一篇论文实验闭环。
