# FishBot 雷达源码说明

本目录保存了 FishBot 初代底盘、导航和雷达链路相关的公开源码。

## Ubuntu 有线直读（当前方式）

按 FishROS 教程把雷达转接板跳线帽切到 **UART 有线档**，用 USB 将板子
接到 Ubuntu。教程还要求拔掉 ESP8266 的 EN 跳线帽。检查串口设备：

```bash
ls -l /dev/ttyUSB* /dev/ttyACM*
```

当前电脑检测到 CH340 串口 `/dev/ttyUSB0`。直接运行纯 Python 接收程序：

```bash
cd /media/scc/Windows_D/AAA/abc
python3 read_lidar_wired.py --port /dev/ttyUSB0
```

本机实测：约 6 秒内收到 41,426 字节，解码 535 包，校验失败 0 包，
已输出角度与距离。这说明当前接入的雷达在有线模式下可按此数据协议读取。

程序以 115200、8N1 读取，并打印角度和距离；不需要 ROS 2 或第三方
Python 包。如需保存数据，加 `--csv lidar_points.csv`；若有字节但不能
解码，加 `--raw lidar_raw.bin` 保存原始字节。若显示 0 字节，检查跳线、
雷达供电和电机是否在转；若有字节但始终 0 包，核对波特率和雷达协议。

### 发布 ROS 2 `/scan` 并在 RViz2 查看

本目录另有 [read_lidar_ros2.py](read_lidar_ros2.py)，直接读取
`/dev/ttyUSB0`，按每圈组装 `sensor_msgs/msg/LaserScan` 并发布 `/scan`。
不需编译功能包。不要同时运行 `read_lidar_wired.py` 或其他雷达驱动，
否则会争用同一个串口。

终端一：

```bash
source /opt/ros/jazzy/setup.bash
cd /media/scc/Windows_D/AAA/abc
python3 read_lidar_ros2.py
```

终端二：

```bash
source /opt/ros/jazzy/setup.bash
rviz2 -d /media/scc/Windows_D/AAA/abc/lidar.rviz
```

RViz2 配置已设 Fixed Frame 为 `base_link`、LaserScan 话题为 `/scan`。
脚本默认使用 `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`，
该路径在本机对应 CH340 转接板，拔插后仍可指向新的 ttyUSB 编号；
若你的设备路径不同，用 `--port` 指定。脚本会临时发布一个单位变换
`base_link -> laser_frame`，仅用于独立预览。若底盘已经发布真实雷达 TF，
启动脚本时加 `--no-preview-tf`，避免重复发布。当前机器实测 `/scan` 约
每秒 8 圈，每圈约 250–300 个有效角度格。

## Ubuntu Wi-Fi 读取雷达数据（无需 ROS 2）

先在 Ubuntu 终端运行 `ip -4 addr`，找到连接到雷达所在 2.4 GHz Wi-Fi
网络的网卡地址，例如 `192.168.1.102`。这个地址要填到转接板的 `server_ip`，
不能填转接板自身的 IP、`127.0.0.1` 或 Docker 网卡地址。

按板上标记将转接板跳线帽切到 Flash/配置档，用 USB 连接 Ubuntu 电脑。
打开 FishBot 配置助手，设备类型选“FishBot 雷达转接板”，刷新并选中对应
串口，再用“重新扫描配置”读取现有参数。设置：

```text
wifi_ssid    = 你的 2.4 GHz Wi-Fi 名称
wifi_pswd    = Wi-Fi 密码
server_ip    = 上一步查到的 Ubuntu 电脑 IPv4 地址
server_port  = 8889
net_mode     = tcp
laser_baud   = 115200
```

若配置助手把端口显示成 `tcp:8889`，其中 `tcp` 是模式，`8889` 是端口。
保存后断电，把跳线帽切回 Wi-Fi 档，再重新上电。仅修改运行中的电脑 IP
不会自动更新转接板配置；电脑换网络或 IP 改变时需重新设置 `server_ip`。

也可通过 Flash/配置档的 115200 波特串口发送下列命令；每行以换行结束：

```text
$command=read_config
$wifi_ssid=你的WiFi名称
$wifi_pswd=你的WiFi密码
$server_ip=192.168.1.102
$server_port=8889
$net_mode=tcp
$laser_baud=115200
$command=read_config
```

示例中的 `192.168.1.102` 必须替换为电脑的实际地址。固件收到设置命令后
返回 `$result=ok`；第二次 `read_config` 用于核对保存结果。这个串口方法
来自本目录的转接板固件源码，若设备固件版本不同，优先使用配置助手。

接着在 Ubuntu 上运行接收程序：

```bash
cd /media/scc/Windows_D/AAA/abc
python3 read_lidar_wifi.py
```

默认监听 TCP 8889。若 Ubuntu 防火墙启用，需允许这个 TCP 端口接入。
程序显示“转接板已连接”说明网络通了；出现“第 N 包，N 个有效点”才说明
已解码出测距数据。

## Windows 上直接读取雷达数据（无需 ROS 2）

运行 [read_lidar_wifi.py](read_lidar_wifi.py)，需要 Python 3，不需要安装第三方包：

```powershell
cd D:\AAA\abc
py -3 .\read_lidar_wifi.py
```

如需保存每个有效测距点：

```powershell
py -3 .\read_lidar_wifi.py --csv .\lidar_points.csv
```

如果有网络数据但无法解码，可保存原始字节供后续分析：

```powershell
py -3 .\read_lidar_wifi.py --raw .\lidar_raw.bin
```

上面的 `D:\AAA\abc` 仅为示例，请换成你的实际 Windows 路径。程序默认监听
TCP 8889。转接板必须为 TCP 模式，`server_ip` 填这台 Windows 电脑在同一
Wi-Fi 网络中的 IPv4 地址，`server_port` 为 8889，`laser_baud` 为 115200。
用 `ipconfig` 查询电脑的 IPv4 地址。若 Windows 防火墙提示，允许 Python
在当前网络接收连接。先运行程序，再给雷达转接板上电。

看到“转接板已连接”仅代表网络连接成功；还需看到“第 N 包，N 个有效点”
才说明雷达数据已解码。若收到字节但始终为 0 包，需核对雷达协议、波特率和
转接板模式。当前雷达在有线模式下已按 S2/X2 数据协议成功解码；Wi-Fi
转发链路仍需单独验证。
这个接收程序适合验证和读取数据；它不发布 ROS 2 `/scan` 话题。

FishROS 教程“可视化雷达点云-学会驱动雷达”说明的正是雷达转接板通过 TCP
连接到电脑的 8889 端口，再交给上位机处理的链路。本目录的 Windows 程序
直接处理数据包，因此不需要教程中的 Linux 虚拟串口步骤。

## 目录用途

- `motion_control/`：FishBot micro-ROS 底层运动控制固件，不负责解析激光雷达数据。
- `nav/`：FishBot 上位机建图和导航代码，消费 `/scan` 话题。
- `radar_adapter_firmware/`：FishBot 雷达转接板（ESP8266）固件，把雷达串口数据通过 TCP/UDP 转发到控制电脑。
- `ros_serial2wifi/`：ROS 2 网络转虚拟串口桥；TCP 默认监听 `8889`，可生成 `/tmp/tty_laser`。
- `ydlidar_ros2_driver/`：YDLIDAR 官方 ROS 2 驱动，读取串口并发布 `sensor_msgs/msg/LaserScan` 类型的 `/scan`。
- `ydlidar_sdk/`：YDLIDAR ROS 2 驱动依赖的底层 SDK。

## FishBot 雷达数据链路

```text
YDLIDAR 雷达
  -> FishBot 雷达转接板
  -> Wi-Fi TCP/UDP
  -> ros_serial2wifi
  -> /tmp/tty_laser
  -> ydlidar_ros2_driver
  -> /scan
  -> Cartographer / Nav2
```

若雷达直接用 USB 连接电脑，则不需要 `radar_adapter_firmware/` 和
`ros_serial2wifi/`，将驱动的 `port` 配成 `/dev/ttyUSB0`（以实际设备名为准）即可。

## 初代导航源码中的兼容问题

`nav/src/fishbot_bringup/launch/bringup.launch.py` 不能直接配合当前驱动运行：

1. 文件中写的是 `ros_serail2wifi`，公开仓库里的实际包名是
   `ros_serial2wifi`。
2. 文件中使用旧驱动包 `ydlidar`；本目录下载的当前官方 ROS 2 驱动包名是
   `ydlidar_ros2_driver`，启动文件也应使用该包的
   `launch/ydlidar_launch.py`。
3. FishBot 的网络雷达链路应将 YDLIDAR 参数 `port` 指向
   `/tmp/tty_laser`，并让转接板端口和 `ros_serial2wifi` 的监听端口一致。
4. 波特率、单通道模式、采样率等参数必须按实际雷达型号选择，不能只凭底盘型号确定。

## 已知接口

- 雷达话题：`/scan`
- 雷达坐标系：`laser_frame`
- 导航代价地图输入：`/scan`
- FishBot 示例虚拟串口：`/tmp/tty_laser`
- 当前 `ros_serial2wifi` 默认 TCP 端口：`8889`

## YDS2MD-1 试运行配置

已知雷达标签为 `YDS2MD-1 2104M4342`。`2104M4342` 暂按产品序列号处理；
未找到能据此确认协议版本的厂商资料。`YDS2MD-1` 的公开参数与 YDLIDAR S2
相近，因此增加了一个 S2 兼容的试运行配置：
`nav/src/fishbot_bringup/launch/yds2md_lidar.launch.py`。配置为 115200 波特、
3 kHz、单通道、0.12–8 m，输出 `/scan` 和 `laser_frame`。

如果使用 FishBot Wi-Fi 雷达转接板，且转接板设为 TCP 模式并连接到电脑的
8889 端口（目前启动文件默认采用此方式）：

```bash
ros2 launch fishbot_bringup yds2md_lidar.launch.py
```

USB 直连电脑时：

```bash
ros2 launch fishbot_bringup yds2md_lidar.launch.py use_wifi:=false port:=/dev/ttyUSB0
```

该 launch 只启动雷达链路；底盘和 TF 可用原来的 `bringup_quick.launch.py`
启动。执行 `ros2 topic echo /scan --once` 检查是否有数据，再运行建图或导航。
若雷达电机不转，应先检查硬件供电及电机控制线；仅设置 ROS 参数不能替代
电机控制。当前雷达通过本目录的纯 Python 程序在有线模式下已验证数据包；
此 ROS 2 launch 和 Wi-Fi 转发链路尚未实机验证。

进一步完整联调仍需确认：

- 雷达通过 USB 直连还是 FishBot Wi-Fi 转接板连接；
- 实际的串口设备名或 Wi-Fi 转接板所连的电脑 IP 和端口。

当前检查到这台电脑安装了 ROS 2 Jazzy。Wi-Fi 转接板默认的雷达波特率为
115200，网络模式为 TCP，电脑端口为 8889，目标 IP 为 `192.168.4.1`；
这些是固件源码的出厂默认值，若曾用配置助手修改过，需要以转接板的实际
配置为准。控制电脑必须能在转接板所连网络中以这个 IP 接收连接。
