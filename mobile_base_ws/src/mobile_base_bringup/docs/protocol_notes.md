# 协议说明与实现假设

## DM-J4340P-2EC 24V

- 初始方案采用 1 Mbps 经典 CAN。传输接口已经预留 CAN-FD 支持，但示例 URDF 默认关闭 CAN-FD。
- 转向采用位置速度模式，CAN 标识符为 `0x100 + motor_id`。8 字节数据由两个小端序 `float32` 组成：目标位置（rad）和最大转动速度（rad/s）。
- 实物电机需设置 `CTRL_MODE=2`。`configure_damiao_mode.py` 可在底盘节点停止时读取或切换寄存器 `0x0A`；默认只写 RAM，保存 Flash 需要独立二次确认。正常底盘启动不会自动修改内部参数。
- `motor_id` 对应电机的 `ESC_ID`，`master_id` 对应反馈 `MST_ID`。四台电机的这两项在 xacro 的四个 `dm4340p_joint` 调用处配置，必须与官方软件写入电机的值一致。示例为每台电机分配独立 `MST_ID`。
- 新版官方 SDK 的使能、失能和设零特殊命令始终使用 `ESC_ID`，数据为 8 字节 `FF ... FC/FD/FE`；本工程不发送 `FE` 设零命令。
- 状态反馈解析内容包括：电机 ID、状态码、16 位位置、12 位速度、12 位转矩、MOS 温度和转子温度。状态码 `0` 表示失能，`1` 表示正常使能，其他非正常代码按故障处理。
- 启动时必须从每台电机读取 PMAX、VMAX、TMAX 寄存器 `0x15/0x16/0x17`。任意电机读取失败、返回非有限值或非正数时，硬件配置立即失败，不使能转向和行走驱动器。
- 配置阶段读取 `0x51 (xout)`。该值由输出轴编码器直接测量，单位为 rad，用于初始化每个转向关节的绝对角度，并对齐后续状态反馈。
- `0x14 (Gr)` 实机回读为 `40.0`，但它不能直接作为位置速度帧的机械角倍率；驱动不会用它乘除目标角。网页维护使用带唯一编号的相对角命令，上限可配置为 1°～360°，同一次按住的心跳不会重复累加。
- 参数读取和主动刷新都发送到 `0x7FF`：D0/D1 为 ESC_ID 低/高字节，D2 为命令字 `0x33/0xCC`，D3 为寄存器号或零。
- 软件不会发送“设零”指令。车轮机械朝前的偏差由 URDF 中每个模块的 `offset_rad` 修正。
- 不使用其他达妙型号的固定量程作为回退值。反馈报文只有在实际量程读取成功后才会解析，控制指令也只有在量程有效时才允许发送。
- 当前使用 24V 版本，四个轮组的初始最大转向速度均设为 `0.5 rad/s`。该值来自 `chassis.yaml` 的 `max_velocity_rad_s`，启动文件会逐轮传入 Xacro；完成架空调试后才能按实测结果提高。
- 24V 表示动力供电版本，不改变本工程的经典 CAN 报文格式。电机仍需在达妙上位机中设置 `CTRL_MODE=2` 和 1 Mbps，并按实物确认电压、过流和温度保护参数。

## ZLAC8015D

- 依据 ZLAC8015D V4 CANopen 通信说明 V1.01（2026-02-26），采用 500 kbps 经典 CAN 上的 CANopen。驱动器符合 CiA301/CiA402，默认节点号为 1、默认波特率为 500 kbps。
- 当前实现使用加速 SDO，并按照 CiA-402 顺序执行 `6040h = 0x0006 → 0x0007 → 0x000F`。使能后读取合并状态字 `6041h:00`，低 16 位为左电机、高 16 位为右电机；两个通道都必须进入 Operation Enabled。
- 正常停机先给两个通道发送零速，再写 `6040h = 0x0006`，由驱动器按照 `605Bh` 的关闭操作方式减速并退出使能；不把 `0x0000` 的立即失压当作日常停车指令。
- 启动时先发送 CANopen NMT“启动远程节点”，再写入异步控制标志 `200Fh:00 = 0`。
- 工作模式写为 `6060h:00 = 3`（Profile Velocity，轮廓速度模式），并读取 `6061h:00` 确认模式确实生效。
- `2000h:00` 是通信掉线保护时间，单位 ms，手册建议设置为 200~1000 ms。工程默认每次启动写入 500 ms，但不会执行 `2010h:00 = 1`，因此不会主动保存到 EEPROM。
- 左右电机分别使用子索引 1 和 2：
  - `60FFh:01/02`：左右目标速度，默认单位为 1 rpm。
  - `606Ch:01/02`：左右实际速度，默认单位为 0.1 rpm。
  - `6083h:01/02`：左右加速时间，单位 ms。
  - `6084h:01/02`：左右减速时间，单位 ms。
- 运行期每 100 ms 读取 `6041h:00` 和 `603Fh:00`。`603Fh` 为 32 位合并故障码；报警判断以状态字 bit7 为准，故障码用于日志定位，状态字 bit15 作为外部急停状态处理。
- 目标转速在驱动层限制为 ±1000 rpm，避免触发 V4 的“速度给定错误”。目标速度单位仍可在 URDF 中配置，以适配 `2026h:05` 的速度分辨率设置；本工程默认值 1 对应 1 rpm。
- `1017h:00` 支持生产者心跳，单位 0.5 ms。当前第一阶段不修改该持久化通信参数，实际在线判断使用周期速度反馈；后续改为 PDO 时可一并启用心跳监督。
- 当前使用 SDO 适合第一阶段上机调试。通信稳定后，建议将目标速度和实际速度映射到 RPDO/TPDO，以降低总线负载并改善周期同步性。

## 总线分配

- `can1`：4 台 DM-J4340P-2EC 24V，经典 CAN 1 Mbps。
- `can0`：2 台 ZLAC8015D，CANopen 500 kbps，节点 5/6。
- 不建议将两类驱动器放在同一总线上，因为默认波特率、协议语义和故障处理方式不同。
